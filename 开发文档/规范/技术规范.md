# 🔧 技术规范

## 项目架构

```
fox-dashboard/
├── manifest.json      # Obsidian 插件清单
├── main.ts            # Plugin 入口（注册视图、设置、命令）
├── view.ts            # FoxDashboardView（核心渲染 + 数据逻辑）
├── styles.css         # 双主题 CSS（~1200 行）
├── package.json       # 依赖 + build 脚本
├── esbuild.config.mjs # 打包配置
├── tsconfig.json      # TypeScript 配置
├── main.js            # 编译产物（gitignore 建议）
└── 开发文档/
    ├── 日志/           # 开发日志 + 待办
    └── 规范/           # 需求/技术/设计/执行/文件地图
```

## 技术栈

| 层级 | 选型 |
|------|------|
| 运行时 | Obsidian Plugin API（ItemView, TFile, Plugin） |
| 语言 | TypeScript（ES6 target, ESNext module） |
| 打包 | esbuild（external: obsidian, electron） |
| 样式 | 纯 CSS（CSS 变量驱动双主题） |
| 数据持久化 | `plugin.loadData/saveData`（settings.json） |
| 文件 I/O | `app.vault.adapter.read/write/exists` |
| 资源路径 | `app.vault.getResourcePath(TFile)` via `getAssetPath()` |

## 核心约定

### 1. 双主题机制
- CSS 变量的 `day` 主题在 `.fox-dashboard-view` 根选择器定义
- `night` 主题在 `.fox-dashboard-view.fox-night` 覆盖
- 主题切换调用 `render()` 重建 DOM → 触发 `onSettingsChanged()` 重载数据

### 2. 所有资源路径必须用 `getAssetPath()`
```typescript
// 正确：通过 vault 解析为 Obsidian 资源 URL
img.src = this.getAssetPath('assets/icons/孤狼守护者.png');
// 错误：插件视图下不解析
// img.src = 'assets/icons/孤狼守护者.png';
```

`getAssetPath()` 和 `getBgPath()` 从 vault 根目录查找文件。
资源文件位于 vault 根目录的 `assets/` 文件夹下。

### 3. 数据流
```
用户操作 → 修改 settings / 日记文件 → 调用 saveSettings / write
                                        ↓
                              settingsChanged / render → load*
```

### 4. 日记文件格式约定
```yaml
---
date: 2026-07-22
tags: [日志]
mood: 明朗        # 心情（由心情模块维护）
mood_note: 今天天气好  # 心情备注（由心情模块维护）
habits: [早起, 阅读] # 习惯（由习惯模块维护）
---
```

### 5. SVG 热力图约束
- 使用 inline `fill`（非 CSS class），因为 SVG 元素的 `fill` 属性在 Obsidian 插件上下文中有优先级问题
- 4 级密度：`rgba(120,155,88, 0.38/0.56/0.74/0.92)`

### 6. 编译命令
```bash
npx esbuild main.ts --bundle --outfile=main.js --external:obsidian --external:electron --format=cjs --platform=node
```
